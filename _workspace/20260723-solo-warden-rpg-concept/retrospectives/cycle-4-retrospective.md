## 이번 사이클에서 가장 중요한 두 발견

### 1. 포대(Turret) GDD 서술 오류 — "지속 화력 최대"가 실측과 정반대

Checkpoint 1의 시뮬레이션 실측이 GDD의 "포대 = 지속 화력 최대" 서술을 뒤집었다 — 실제로는 3스탠스
중 화력 최저(FRONT 0이 후열 시너지·Boss Rally Window 양쪽 다 배제), 대신 동료 피격량이 정확히 0인
"완전 무피해" 스탠스였다. 이는 코드 리뷰나 설계 논의로는 발견 불가능했고, 결정론적 시뮬레이션을
실제로 구동해 수치를 뽑아본 뒤에야 드러났다 — Cycle 3의 "보스 메시 버그"와 같은 패턴("코드가
그럴듯해 보인다"와 "실제로 그렇게 동작한다"는 다른 주장)의 밸런스판 재현.

### 2. 카메라 힌트 토스트 — 5개 병렬 구현 레인이 각자 클린해도 통합 버그는 남는다

3개(설계는 5개) 병렬 레인이 전부 자기 파일 경계를 정확히 지켰고 diff 리뷰도 전부 클린했지만,
실제 브라우저 실행에서만 발견되는 크로스-레인 셀렉터 충돌이 있었다 — 신규 토스트가 기존의 느슨한
`.edge-card:not(.defense-result)` 셀렉터에 우연히 매치돼 렌더 직후 자동 삭제됨. **코드 diff가
전부 정상으로 보여도, 실제 실행 검증 전까지 "작동한다"고 주장할 수 없다**는 이 프로젝트의 반복된
교훈(D19/D20/Cycle3)이 다시 한번 확인됐다.

## 프로세스 노트

1. **새 리서치 증거가 이미 확정된 사용자 결정을 자동으로 뒤집지 않는다.** 8게임 리서치가 "장르
   표준은 고정 카메라"라는 상반된 증거를 냈지만, D17(이미 확정)을 조용히 되돌리는 대신 사용자에게
   새 증거를 명시적으로 알리고 재확인받았다 — director의 역할은 증거를 감추지 않되, 이미 내려진
   결정을 증거 하나로 일방적으로 뒤집지 않는 것.
2. **병렬 서브에이전트의 "cancelled" 상태가 곧 "실패"는 아니다.** 3개 구현 레인 중 2개가
   타임아웃으로 취소됐지만, transcript를 직접 읽고 git diff/테스트 실행으로 확인한 결과 전부
   완료+자체검증(teeth-test 포함)까지 끝나 있었다 — 상태 라벨보다 실제 산출물 확인이 근거로서
   우선한다.
3. **서비스워커 캐시 함정이 이번 세션에서만 2회 재발**(카메라 힌트 디버깅 중) — D19가 이미 기록한
   교훈인데도 로컬 반복 검증마다 매번 새로 걸렸다. 이 프로젝트에서 PWA 로컬 검증 전 캐시 삭제를
   습관화된 절차로 만들 필요.
4. **GLB 감사 스코프가 처음엔 캐릭터로만 좁게 잡혔다가, 설계 서브에이전트(StageCompositionDesign)의
   지적으로 터레인까지 확대됐다** — 카메라 자유도 확대가 배경/지형에도 동일한 리스크를 만든다는
   것을 처음에는 놓쳤다. 자유 궤도/회전 카메라를 도입할 때는 "캐릭터"뿐 아니라 "카메라가 보게 될
   모든 것"을 감사 스코프로 잡아야 한다.
