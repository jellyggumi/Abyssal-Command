# Lobby Concept — Game-Programmer Position (출정/sortie surface)

*Author: game-programmer. Grounded in `app.js` (render path + RAF loop), `battle-realtime-three.js` (the shared-thread canvas), and the survey outputs (`adoptable-pattern-shortlist.md`, `context.md` performance bullets, `qa/benchmark-notes.md`). Technique-only — no code.*

## Position

The single most important engineering fact about this lobby is that **the live canvas is already running a full 60Hz WebGL frame in the lobby** — `loop()` (app.js:1449) re-arms `requestAnimationFrame(this.loop)` unconditionally and calls `render()`→`renderSnapshot()` every frame regardless of `started`; when `started=false` it merely *skips the sim* (`advanceDefenseRun` inside the `this.started && …` guard, app.js:1472) while still stepping mixers, reconciling actors, and issuing `renderer.render(scene, camera)` (battle-realtime-three.js:2057-2088). So the correct mental model is: in the lobby the **GPU/scene draw is fully paid every frame, but the entire defense-sim JS budget is free** (dozens of actors, AI, collision, projectiles, events — all idle). Lobby juice is therefore cheap *if and only if it stays on the CSS compositor thread (transform/opacity) or in free main-thread JS, and does NOT add three.js scene objects, shaders, or backdrop-blur surfaces that inflate the already-running draw*. My recommendation: build ALL lobby theater from the CSS motion vocabulary the codebase already ships (`.rc-lift`, `.dock-panel { transition: transform }`, `world-damage-rise`, `rc-glow-ring`, bar `transition: width`), add exactly one bounded one-shot JS count-up for the idle-return "payday" (A1), and make A6 "emit-from-canvas" the near-zero-cost reuse of the panel's existing 200ms transform transition plus a static edge seam — deferring true camera-coupled parallax as the one budget risk.

## Concrete lobby changes

- **A1 idle-return "payday" count-up (highest impact, data already present).** `idleReturnSummary()` already returns `receipt.awardedProgress` (the number to count up from 0) and `total` (accumulated) — `renderIdleReturnToast()` (app.js:930) today just drops static text. Technique: a **bounded one-shot count-up** — a fixed ~600-700ms animation that writes `textContent` on a capped cadence (≈30 steps via `setInterval`/`requestAnimationFrame` that *self-terminates*, never a persistent loop), eased toward `awardedProgress`, then a `world-damage-rise`-style transform+opacity reveal (the idiom already at styles.css:240/243) on the number. This is free JS: the sim isn't running, so the main thread is idle. Reduced-motion: check `motionQuery.matches` and paint the final number instantly (mirrors the existing stance-shake gate at app.js:1718 and the bar-transition guards at styles.css:394). Ref: `AFK Arena "welcome back" recap`, benchmark Takeaway on theatricalizing return.

- **A5 always-framed persistent readouts (cheap, static).** Promote the累적/누적 idle total + warden points into permanently-visible framed pills on the dock chrome (`renderDockSide` header, app.js:657-667). Technique: static `.rc-glass`-family pills with a `transition: width`/`transition: color` on value change only — the same 120ms linear fill the XP/integrity bars already use (styles.css:307/327). No new per-frame cost; value only animates on the frame it changes. Ref: `vampire-survivors-stage-selection.jpg` top-center gold pill "3679"; benchmark Calibration Takeaway 2.

- **A6 dock "emit from / attach to" the canvas (signature, near-zero cost baseline).** `.dock-panel` *already has* `transition: transform 200ms ease` (styles.css:58) and the panels *already sit over the live scene via `.rc-glass` backdrop-blur* (styles.css:506) — they are visually "of the world" today; the gap is they pop rather than emit. Technique (all compositor-thread): (a) open/close = the panel starts translated toward its canvas-facing edge and settles via the existing transform transition — a slide "peeling off" the scene, zero new JS; (b) a **static** 1px edge-seam gradient (cyan-rift→transparent) on the panel edge that faces the canvas so it reads as attached, not pasted — no animation, no cost; (c) DO NOT add new glass/blur surfaces — `backdrop-filter: blur(10px)` resamples the live canvas every frame per panel and is already the single biggest recurring lobby cost. Ref: A6 shortlist "panels slide/emit from the canvas edge… NO heavy shaders"; benchmark Takeaway 6 "make the menu a place."

- **Sub-100ms tap feedback on every sortie control (A6 touch requirement).** Reuse `.rc-lift` (transform translateY + box-shadow, styles.css:509-511) as the press-scale on stage cards (`.stage-card` already carries `rc-lift`, app.js:793) and the START FAB. For a bursty "confirm" on the FAB tap, use a **DOM/CSS sprite or pooled-DOM particle** — a single absolutely-positioned element animated with a `steps()` `background-position` sprite-sheet, or 3-5 pooled `<span>`s animated with transform+opacity then recycled — living in screen-space, NOT three.js scene VFX. Compositor-thread, off the WebGL draw entirely. Reduced-motion fallback: a static pressed border/background state so the <100ms feedback stays *perceivable* when the scale tween is suppressed by the global `animation:none` rule (styles.css:248). Ref: context.md "juice = button scale + particle burst"; touch constraint ≥48dp / sub-100ms.

- **Selected-stage-card "live" highlight (A6, budget-capped).** The selected `.stage-card` already gets `rc-glow-ring` (app.js:793) — the animated conic-gradient border (`@property --rc-glow-angle`, styles.css:516-526). Keep it, but **cap it to exactly one visible glow ring at a time** (only the selected card): an animated conic-gradient repaints its border layer every frame, so multiplying it across the stage rail would stack repaints onto the already-running draw. Non-selected cards use the cheaper static border. Ref: `soulstone-survivors-skilltree.jpg` selected-node highlight; A6.

- **START/작전 개시 CTA as the one warm high-attention CTA (polish target for pattern #1).** The FAB (`renderSortieFab`, app.js:900) is the 12/13 "central Play→run" pattern and must stay in the thumb zone (`position:fixed; bottom; translateX(-50%)`, styles.css:104-109) and route straight to combat. Technique: a single cinder-ember fill + a slow ambient `box-shadow`/opacity breathe (compositor-only, one element), plus the `.rc-lift` press. Ref: `vampire-survivors-itch-browser-menu.png` — one unmistakable START; `vampire-survivors-stage-selection.jpg` green START bottom-right.

- **(Optional, flagged) idle-cadence throttle for extra headroom.** Because the lobby draws a full frame every 16.67ms (`STEP_MS = 1000/TICK_RATE`, app.js:48) with the sim off, an *option* is to render the canvas every Nth frame while `started=false` and the tab is focused, reclaiming GPU headroom. This is a canvas-loop change (not pure CSS), must not visibly stutter the idle breathing animations, and the existing `recordFrameProbe` telemetry (app.js:1483) is the guardrail to prove it before/after. Present as a stretch, not the safe baseline.

## Risks / disagreements

- **Where I expect to diverge from the designer/UI:** they will likely want richer, more numerous animated surfaces (multiple glow rings, card-flip reveals, animated hub inhabitants, more glass panels). My hard line: **the cost isn't the CPU — it's the GPU/scene draw that runs every lobby frame.** Every additional `backdrop-filter: blur` panel and every animated conic-gradient ring stacks onto a frame that's *already fully drawing the 3D scene*. Adding three.js scene VFX or reactive scene inhabitants for lobby juice is the most tempting and the most expensive idea; I'll push those out of the first pass. Compositor-thread transform/opacity motion is nearly free; scene-graph and blur are not — the mockup should not imply a dozen simultaneously-animating panels.
- **The one genuine budget risk I'm flagging:** true camera-coupled dock **parallax** (dock transform bound to the canvas camera orbit). It requires a per-frame JS write co-scheduled with the canvas RAF — exactly the pattern that contends for the single 16.67ms frame. If the group wants it, it must be ONE throttled transform on ONE dock container, gated on reduced-motion, and validated via `recordFrameProbe` before/after on a real mid-tier device — not fanned out across panels. Safe baseline ships without it (the static edge seam + existing slide transition already sell "attached to world").
- **Reduced-motion is not a toggle-off afterthought:** the global `animation:none !important; transition:none !important` (styles.css:248) will silently kill every effect I propose, so each must have a meaningful *resting* state — the count-up must land on the final number, the selected card must keep a static border, tap feedback must keep a static pressed state, panels must open to their final position. I'll insist the mockup/spec name those resting states, because "juice" that vanishes entirely under reduced-motion fails the accessibility gate (G4).
- **Load-time caveat:** context.md flags ~53% mobile bounce >3s. None of my proposed juice is load-bearing on first paint (it's all post-mount CSS + a lazy toast), so it doesn't threaten first-paint — but I'll resist any request to preload heavier lobby assets/shaders that would.
