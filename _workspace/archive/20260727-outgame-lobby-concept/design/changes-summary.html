독이 라이브 씬에서 "떨어져 나온" 것처럼

After · 캔버스와 맞닿는 독 가장자리에 정적 1px cyan-rift 씸 — 씬에서 emit된 것처럼 읽힘 (per-frame 비용 0)

A5 · 상시 통화 readout

상단 2개 통화 pill (이전엔 0개)

Before · 로비에 보유 재화 표시가 전혀 없음 — 독을 열어야만 확인
After · 좌상단 상시 pill ◈ Echo Core ✦ Bound Fragment — 값 = 성장/인벤토리 독의 소비 잔액과 동일. 탭하면 해당 독으로 딥링크. 전투 시작하면 자동 숨김. 딱 2개(통화 수프 방지)

A2 · 보상-우선 브리핑

스펙시트 → 보상 헤드라인 + 접힌 상세

Before · 지형/위협/점유/랜드마크/보상 5행 스탯 dl이 항상 펼쳐진 "폼"
After · "승리 시 → [다음 보상]" 골드 헤드라인이 먼저, 나머지 지형 4행은 「전황 상세 ▸」 기본 접힘(데이터 보존, 중복 보상행만 제거). 브리핑은 몇 초면 읽는 위협+보상 읽기로

A3 · A4 · 스테이지 맵

선택 카드 확장 + 봉쇄선 스파인

Before · 균등한 스테이지 카드 세로 스크롤(리스트)
After · 선택 카드 확장(밝은 테두리 + 큰 아트) + ✦ 보상 칩; 와이드(≥900px)에선 카드들이 봉쇄선 스파인에 노드 점(clear=held / 선택=cyan 발광 / 잠김=dark)으로 연결 — "전선이 많다"가 한눈에. 모바일은 grid↔상세 읽기(스파인 없음)
styles.css · .stage-card.is-selected / .stage-rail::before spine / .stage-card::after dots · app.js reward chip
5
A1 · idle-return "payday"

무음 잔고 증가 → 골드 카운트업 연출

Before · 복귀 시 정적 텍스트 토스트("정산 완료 +N")
After · SETTLED일 때 0→+N 골드 카운트업(자기종료 rAF, ~600ms) + 상승 리빌; 탭하면 스킵; FAB 절대 안 가림; 실제 경과시간에만(로그인 leash 아님). reduced-motion이면 최종 숫자 즉시 표시
app.js · renderIdleReturnToast (idle-payday count-up)
6
패턴 #1 · 커밋 CTA

작전 개시 = 화면 유일한 ember 요소 + 탭 juice

Before · 평범한 시안 테두리 버튼
After · 작전 개시 유일한 ember 채움 + :active 스케일 + 풀드 DOM 파티클 버스트(스크린-스페이스, three.js 아님) + 은은한 breathe. reduced-motion이면 정적 눌림 상태로 대체
app.js · renderSortieFab + spawnSortieBurst · styles.css .sortie-fab

A5 · 팔레트 규율

개념 → 결과

회의에서 결정한 방향(스키매틱/무드)과 실제 구현이 어떻게 맞는지.

범위/안전 · 이번 Pass 1은 app.js + styles.css (프레젠테이션 레이어)만 변경 — 시뮬레이션/규칙/카탈로그/렌더러 모듈은 손대지 않음. 라이브 캔버스는 로비에서도 이미 60Hz로 그려지므로 sim JS 예산은 놀고 있어, 모든 연출은 compositor-thread transform/opacity + 자기종료 카운트업 + 풀드 파티클로 값싸게. 신규 blur/three.js VFX/parallax는 이번 패스에서 보류. 모든 애니메이션은 reduced-motion resting state 보유(G4).
