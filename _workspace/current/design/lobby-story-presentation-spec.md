## 2. 매체 선택 규칙

`build-hybrid-game-assets`의 표현 선택 원칙을 서사 비트에 적용한다.

| 비트 성격 | 매체 | 근거 |
|---|---|---|
| 세계관 도입, 감정 고조, 시간 경과 | **사전 렌더 비디오** | 편집·사운드·타이밍을 저작으로 통제 |
| 인물 소개, 장소 제시, 정적 극적 순간 | **연출 스틸 시퀀스** | 비디오 대비 용량 1/20, 해상도 자유 |
| 보스 첫 대면, 스테이지 진입 | **인엔진 카메라 시퀀스** | 실제 모델을 쓰므로 자산 재사용, 용량 0 |
| 로어 보충, 수집물 설명 | **텍스트** | 분량이 많고 건너뛰기 쉬워야 함 |

### 2.1 판단 순서

```
1. 이 비트가 "움직임과 시간"을 필요로 하는가?  예 → 비디오
2. 실제 게임 모델로 표현 가능한가?              예 → 인엔진 시퀀스
3. 한 장면의 인상이 핵심인가?                   예 → 연출 스틸
4. 그 외                                        → 텍스트
```

### 2.2 텍스트 폴백 의무

**모든 미디어 비트는 텍스트 대체본을 갖는다.** 예외 없음.

| 발동 조건 | 동작 |
|---|---|
| 미디어 로드 실패 | 텍스트 대체본 표시 + 재시도 버튼 |
| 오프라인 + 미캐시 | 동일 |
| `prefers-reduced-motion` | 비디오 → 대표 스틸 3장 + 텍스트 |
| 사용자 설정 "텍스트 우선" | 텍스트 대체본을 1차로 |
| 스크린 리더 활성 | 텍스트 대체본 낭독 |

텍스트 대체본은 **자막 전사가 아니라 장면 요약**이다. 무엇이 보이고 무엇이 일어났는지
1–3문장으로 적는다.

## 3. 로비 서사 아카이브 구조

### 3.1 배치 제약 — 사이드독을 깨지 않는다

`[OBSERVED]` 20260727 런에서 전체화면 오버레이(`#command-shell`)는 **명시적으로 제거**되고
좌우 고정 독으로 대체되었다. 서사 열람이 다시 전체화면 오버레이를 도입하면 그 결정을
되돌리는 것이다.

**채택:** 좌측 독에 `기록` 탭을 추가한다. 기존 탭(`성장`/`군단`/`인벤토리`)과 같은 레일에
들어간다. 미디어 재생은 **독 패널 안에서** 일어나며, 전장 캔버스는 계속 보인다.

| 항목 | 규칙 |
|---|---|
| 진입 | 좌측 독 → `기록` 탭 |
| 재생 영역 | 독 패널 폭에 맞춘 16:9 프레임 |
| 확대 | 탭 시 **독 폭의 2배까지만** 확장. 전체화면 없음 |
| 배경 | 전장 캔버스 유지 (가리지 않음) |
| 종료 | 탭 전환 또는 `닫기` |

### 3.2 항목 구조

스테이지당 3비트 = 10 × 3 = **30 항목**.

| 비트 | 해금 조건 | 내용 |
|---|---|---|
| `approach` 진입 | 스테이지 최초 진입 | 장소와 위협 제시 |
| `confrontation` 대면 | 보스 최초 조우 | 보스 정체 |
| `aftermath` 여파 | 스테이지 클리어 | 결과와 다음 실마리 |

### 3.3 스포일러 규율

`[OBSERVED]` 현행 로비는 `STAGE_SHOWCASE_IDS` 3개 전선만 이름·브리핑을 공개하고 나머지는
봉인 처리한다. 서사 아카이브도 같은 규율을 따른다.

| 상태 | 표시 |
|---|---|
| 미도달 스테이지 | 봉인 카드 — 제목·썸네일·내용 전부 숨김. `"봉인된 기록"` |
| 도달, 비트 미해금 | 제목만. 썸네일 실루엣 |
| 해금 | 전체 표시, 재생 가능 |

**해금된 비트는 언제든 다시 볼 수 있다.** 1회성 소비가 아니다.

## 4. 비디오 사양

### 4.1 정적 호스팅 제약

`[OBSERVED]` GitHub Pages 정적 배포 + 커밋 allowlist. 스트리밍 서버가 없으므로 **파일이
곧 대역폭**이다.

| 항목 | 값 |
|---|---|
| 컨테이너 | MP4 |
| 코덱 | H.264 Baseline/Main (기존 자산과 동일) |
| 오디오 | AAC-LC 48 kHz stereo, **또는 무음** |
| 해상도 사다리 | 720p (기본) / 480p (저대역) |
| 프레임률 | 25 fps (기존 자산 준수) |
| 비트당 길이 | **8–15 s** |
| 비트당 용량 목표 | **≤ 700 KB** |
| 포스터 프레임 | WebP, ≤ 40 KB, 필수 |

### 4.2 용량 예산

기존 자산 `[OBSERVED]`: 32.20 s / 1.5 MB = **약 47 KB/s**.

| 시나리오 | 비디오 비트 수 | 예상 용량 |
|---|---|---|
| 전 30비트를 비디오로 | 30 | 30 × 700 KB = **21 MB** |
| 비디오 10 + 스틸 20 | 10 | 10 × 700 KB + 20 × 120 KB = **9.4 MB** |
| **채택: 비디오 6 + 인엔진 10 + 스틸 14** | 6 | 6 × 700 KB + 14 × 120 KB = **5.9 MB** |

**채택안 근거:** 21 MB는 정적 호스팅 + 서비스워커 캐시에 과하다. 비디오는 **가장 감정
비중이 큰 6비트**에만 쓴다(§7).

### 4.3 자동재생 현실

모바일 브라우저는 **음성이 있는 자동재생을 차단**한다.

| 규칙 | 내용 |
|---|---|
| 기본 | `muted` + `playsinline` + 사용자 탭으로 재생 시작 |
| 자동재생 | 하지 않는다. 포스터 + 재생 버튼 |
| 음성 | 재생 후 사용자가 음소거 해제 |
| 오디오 언락 | 첫 탭에서 처리 (`ui#8` 검사 21과 공유) |
| `preload` | `none` — 탭 진입만으로 다운로드하지 않는다 |

### 4.4 자막

| 항목 | 규칙 |
|---|---|
| 형식 | WebVTT (`<track kind="captions">`) |
| 기본 | **ON** |
| 언어 | 한국어 |
| 대사 없는 비트 | 상황 자막 (`[재가 무너진다]`) |

### 4.5 오프라인 캐시

`[OBSERVED]` `sw.js`가 런타임 파일과 전투 프레임을 캐시한다.

| 자산 | 서비스워커 캐시 |
|---|---|
| 포스터 이미지 30장 | **캐시** (총 ≈1.2 MB) |
| 연출 스틸 | **캐시** (≈1.7 MB) |
| 비디오 6개 | **캐시 안 함** — 최초 재생 시 네트워크, 브라우저 HTTP 캐시에 의존 |
| 텍스트 폴백 | **캐시** (JS 번들에 포함) |

비디오를 서비스워커에 넣지 않는 이유: 4.2 MB를 설치 시점에 강제 다운로드하면 첫 진입이
느려진다. 오프라인에서 비디오 비트는 **포스터 + 텍스트 폴백**으로 성립한다.

## 5. 연출 스틸 사양

| 항목 | 값 |
|---|---|
| 종횡비 | 16:9 (독 프레임과 일치) |
| 해상도 | 1280×720 @1x, 1920×1080 @2x |
| 형식 | WebP (불투명), 품질 82 |
| 장당 용량 | ≤ 120 KB |
| 시퀀스 길이 | 3–5장 |
| 장당 표시 | 3.5 s (사용자 탭으로 즉시 넘김) |

### 5.1 모션 규칙

| 효과 | 기본 | reduced-motion |
|---|---|---|
| Ken Burns (스케일 1.0 → 1.06) | 3.5 s 선형 | **정지** |
| 크로스페이드 | 400 ms | 즉시 전환 |
| 레이어 패럴랙스 (전경/후경 2층) | ±12 px | 0 |

### 5.2 색 보정

`camera-vfx-direction.md#6`의 심연 팔레트를 따른다. 서사 스틸은 게임플레이 색 위계와
**구분되어야** 한다:

| 게임플레이 | 서사 스틸 |
|---|---|
| 위험 적 `#FF3B30` | 서사에서 위험 적을 쓰지 않는다 |
| 채도 높은 스킬 색 | 저채도 그레이딩 (채도 −30%) |
| 고대비 | 중간톤 압축 |

서사 스틸이 게임플레이와 같은 색 언어를 쓰면 "이것이 위험 신호인가"를 순간 혼동한다.

### 5.3 내레이션 없이 비트를 전달하는 방법

| 장치 | 예 |
|---|---|
| 시선 유도 | 인물 시선 방향에 다음 컷의 대상 배치 |
| 규모 대비 | 1컷 인물 클로즈업 → 2컷 광각으로 위협 크기 노출 |
| 상태 변화 | 같은 구도 2컷, 전/후 차이만 |
| 상징 반복 | 등불·사슬·재 — 스테이지 모티프의 시각 반복 |

### 6.2 자산별 출처 기록 의무

모든 런타임 미디어는 `.provenance.json`을 동반한다.

```json
{
  "assetId": "story-s1-approach-still-01",
  "representation": "generated-2d",
  "source": "<생성 도구 / 저작자>",
  "generationInput": "<프롬프트 또는 저작 노트>",
  "license": "<라이선스>",
  "createdAt": "2026-07-28",
  "usedIn": ["lobby-archive"],
  "derivedFrom": null
}
```

`representation`은 4값 중 하나: `imported` / `procedural` / `generated-2d` /
`reference-only`. **`reference-only`는 런타임에 실릴 수 없다.**

### 6.3 인엔진 시퀀스

인엔진 비트는 미디어 파일이 아니라 **카메라 키프레임 데이터**다.

| 항목 | 값 |
|---|---|
| 저장 | `defense-catalog.js`의 authored 데이터 |
| 재생 | 로비 독 안의 소형 Three.js 뷰 (기존 보스 포트레이트 렌더 재사용) |
| 사용 모델 | 이미 allowlist에 있는 GLB |
| 추가 용량 | **0** |
| 폴백 | WebGL 실패 시 포스터 스틸 |

### 7.1 용량 검산

| 매체 | 개수 | 단가 | 소계 |
|---|---|---|---|
| 비디오 | 6 | 700 KB | 4.2 MB |
| 스틸 | 14 시퀀스 × 평균 3.4장 = 48장 | 120 KB | 5.8 MB |
| 포스터 | 30 | 40 KB | 1.2 MB |
| 인엔진 | 10 | 0 | 0 |
| **합계** | | | **11.2 MB** |

**§4.2의 채택안 5.9 MB를 초과한다.** 스틸 48장이 원인이다. 조정:

| 조치 | 절감 |
|---|---|
| 스틸 품질 82 → 76 | 120 → 92 KB, −1.3 MB |
| 시퀀스당 최대 4장으로 제한 (10번 5장 → 4장) | −0.1 MB |
| @2x 스틸을 상위 6비트에만 제공 | −0.9 MB |
| **조정 후** | **≈8.9 MB** |

8.9 MB는 서비스워커 캐시 대상(스틸 4.4 MB + 포스터 1.2 MB = 5.6 MB)과 네트워크 온디맨드
(비디오 4.2 MB, 캐시 제외)로 나뉜다. **설치 시 강제 다운로드는 5.6 MB**다.

### 7.2 Pages allowlist 영향

`PAGES_RUNTIME_PATHS`에 30 포스터 + 48 스틸 + 6 비디오 + 30 VTT = **114 경로**가 추가된다.
현행 allowlist는 약 90 경로 `[OBSERVED]`이므로 **2배 이상 증가**한다.

**엔지니어링 결정 필요:** 경로를 일일이 나열하는 현행 방식은 유지보수가 어려워진다.
디렉터리 단위 allowlist(`assets/story/**`)로 전환할지, 나열을 유지할지 결정해야 한다.
워크플로가 `test -f "$path"`로 존재를 검증하므로(라인 205), 디렉터리 전환 시 검증 로직도
바뀐다.
