# 캠페인 스킬 가시성 진단

대상: `campaign.html` → `app.js` + `battle-realtime-three.js`. 상태: **진단 완료 — 수정 대기.**

## 0. 질문: "스킬이 사용되는지 알 수가 없다"
결론: **스킬은 정상 작동한다. 다만 캐스트가 "내가 스킬을 썼다"로 읽히지 않는다.** 시스템 결함이 아니라 연출 가시성 문제다.

## 1. 스킬 캐스트 경로는 정상 (실측 증거)
브라우저에서 `spawnVfx`를 계측하고 실제 Echo Bolt(rift-bolt) 버튼을 눌러 확인:
- `SKILL_CAST {vfx:"rift-bolt"}` 이벤트가 tick 1070에 `spawnVfx`에 **도달**(로그 실측).
- 같은 틱에 `SKILL_RESOLVED_DAMAGE` 발생 → 데미지 해결됨.
- 버튼이 즉시 "6.2s" 쿨다운으로 전환 → 캐스트 수락됨.
- 캡처 프레임(`campaign-skill-cast.png`)에 캐스트 버스트(흰/핑크 플레어)와 AoE 링이 렌더됨.
- 과거 `effectAnchor`의 `SKILL_CAST → null` 결함은 **이미 수정**됨(코드 주석 확인, `case "SKILL_CAST"`가 커맨더 앵커 반환).
- 스킬 GLB 3종 전부 디스크에 존재(154/199/85 KB). 테스트 환경의 GLB URL 에러는 Node에 `fetch`가 없어서지 브라우저와 무관.

## 2. 그런데 왜 "안 보이나" — 실제 원인 3가지
1. **캐스트 VFX가 앰비언트 스테이지 GLB를 재사용.** 7개 스킬이 단 3개 GLB를 공유하고, 그 3개는 스테이지 배경 연출과 **동일한 에셋**(`cinder-span-ember-wake` / `echo-throne-fracture-echo` / `abyss-chancel-mirror-static`). 그래서 캐스트가 배경 앰비언스와 구분되지 않는다. `battle-realtime-three.js:423-431`
2. **짧고 작다.** 기본 `SKILL_CAST` 수명 30틱(=0.5초), 실루엣도 작음. 스웜 난전 속에서 묻힌다. `:510, :433-443`
3. **캐스트 순간 신호가 없다.** 커맨더 원점의 element 색 플래시, 화면 펄스, 스킬명 콜아웃 등 "지금 이 스킬이 나갔다"를 알리는 전용 큐가 없다.

부수 발견: **스킬은 버튼 클릭으로만 캐스트된다. 단축키(숫자/Q)가 없다.** `app.js:4199-4206` — 키보드 플레이어는 스킬을 쓸 방법이 사실상 없다(이전 스모크에서 Digit1이 무반응이던 이유).

## 3. 수정 옵션
- **A. 캐스트 시그니처 플래시(최고 신호·저비용, 신규 에셋 불요):** `SKILL_CAST` 시 커맨더 원점에 **스킬 element 색**(void/veil/ember/frost) 링 + 밝은 코어 플래시를 짧게. 이미 만든 스파크/링 시스템 재사용. "내가 방금 스킬 썼다"가 즉시 읽힘.
- **B. 스킬 단축키(키보드 캐스트):** 1~7 또는 Q에 active 스킬 바인딩 + 캐스트 시 HUD 버튼 펄스. 키보드 플레이어 접근성 해결.
- **C. 캐스트 수명·밝기 상향 + element 색조 실루엣:** 30틱 → 45~60틱, element 색 틴트로 앰비언스와 분리.
- **D. 스킬별 전용 GLB 7종(근본 해결):** 에셋 파이프라인(god-tibo/blender) 필요 — 무겁고 느림. 별도 사이클 권장.

## 4. 권장
**A + B + C** (신규 런타임 에셋 0, 결정론 안전 — 전부 렌더/입력 레이어). 캐스트가 element 색으로 번쩍이고, 키보드로도 쏘이며, 조금 더 오래 밝게 보인다. D(전용 에셋)는 "진짜" 해결이지만 별도 범위.
