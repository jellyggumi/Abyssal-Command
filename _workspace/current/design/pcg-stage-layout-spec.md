## 1. 평면 규칙 (최우선 · 재협상 불가)

게임플레이는 **단일 평면**에서만 일어난다.

- 계단·경사로·플랫폼·낙차·절벽·다리·턱·구덩이·수직 이동을 **추가하지 않는다.**
- 지름길·아레나·위험 요소·보상·시각적 변화를 위해 게임플레이 고도를 바꾸지 않는다.
- 시각적 높이는 **비보행 배경 장식**으로만 허용한다. 장식은 내비게이션, 카메라 오클루전,
  위협 가시성, 타겟팅, 이동 중 **무엇도** 바꾸지 않는다.

### 1.1 기존 데이터와의 충돌 `[OBSERVED 8.1]` — 엔지니어링 결정 완료

현재 `stage-world-catalog.js#STAGE_WORLD_PROFILES`는 세 stage 모두 하나의
gameplay 평면만 사용한다. 검증기는 다음을 fail-closed로 확인한다.

- obstacle footprint의 `elevation === 0`
- mesh-collider triangle 모든 vertex의 `elevation === 0`
- route waypoint·visibility anchor·NPC·prop placement의 `elevation === 0`
- prop footprint가 arena 안에 있고 gate/critical route를 막지 않음

authored terrain candidate 경로와 provenance는 source evidence로 보존하지만,
현재 candidate GLB는 runtime eligible하지 않다. 따라서 각 profile은
`terrainGlbPath: null`, `terrainRuntimeEligible: false`,
`terrainFallback.kind: "procedural-flat-support"`를 선언한다.
`battle-realtime-three.js#instantiateProceduralTerrain`은 arena bounds 크기의
수평 `PlaneGeometry`를 생성한다. 8–14개의 catalog prop은 이 support plane 위에
개별 clone으로 배치되고 `inspectMeshIntegrity`와 `groundObjectOnPlane`을 거친다.

이 결정은 terrain candidate를 가짜 collision mesh로 승격하지 않으며,
Chancel/Throne의 적격 prop·character asset 로딩을 막지 않는다. 최종 자동 검증은
real-WebGL canonical stage 3/3 및 quoted Node gate 469 tests / 444 pass /
0 fail / 25 existing skips다.

## 2. 셀 그리드

`master-numeric-contract.md#8`의 3 × 2 그리드를 기존 24000 × 12000 아레나에 사상한다.

### 2.1 좌표 산술 (검산 완료)

```
cellWidth  = 24000 / 3 = 8000
cellHeight = 12000 / 2 = 6000
```

| 셀 | 열,행 | x 범위 | y 범위 | 중심 |
|---|---|---|---|---|
| A | (0,0) | 0 – 8000 | 0 – 6000 | (4000, 3000) |
| B | (1,0) | 8000 – 16000 | 0 – 6000 | (12000, 3000) |
| C | (2,0) | 16000 – 24000 | 0 – 6000 | (20000, 3000) |
| D | (0,1) | 0 – 8000 | 6000 – 12000 | (4000, 9000) |
| E | (1,1) | 8000 – 16000 | 6000 – 12000 | (12000, 9000) |
| F | (2,1) | 16000 – 24000 | 6000 – 12000 | (20000, 9000) |

나머지 없이 정확히 분할된다. 기존 `ARENA` 상수를 바꾸지 않으므로 좌표계 재작성이 없다.

### 2.2 이동 시간 검산

지휘관 속도 4100/s `[OBSERVED]` (`defense-catalog.js#COMMANDER.speed`) 기준.

| 구간 | 거리 | 시간 |
|---|---|---|
| 셀 폭 횡단 | 8000 | 1.95 s |
| 셀 대각선 | 10000 | 2.44 s |
| **스폰 셀 중심 → 보스 셀 중심** | **17088** | **4.17 s** |
| 아레나 폭 (참고) | 24000 | 5.85 s |
| 아레나 코너 대각 (참고, 도달 불가) | 26833 | 6.54 s |

**주의:** 스폰→보스 이동은 아레나 코너 대각이 **아니다.** 두 셀의 **중심** 사이 거리다:

```
A(4000,3000) → F(20000,9000)
Δx = 16000, Δy = 6000
d  = √(16000² + 6000²) = 17088
```

코너 대각 26833은 (0,0)→(24000,12000)이며 아레나 바깥 모서리라 플레이어가 설 수 없다.
설계 판단의 근거값은 **17088 / 4.17 s**다.

4.17 s는 5–8분 스테이지에서 이동이 지배적이지 않으면서 "구역을 가로질렀다"는 감각을
남기는 값이다. `transit` 셀을 경유하면 실제 경로는 이보다 길어진다.

### 2.3 셀 구성

6칸 고정 구성: `arena` × 3, `transit` × 2, `boss` × 1.

**`shrine`은 독립 셀이 아니다.** 6칸에 자리가 없다. `shrine`은 `transit` 셀 내부의
**앵커**이며 조건 충족 시(지휘관 30%/40% 이하, `encounter-wave-spec.md#1`) 활성화된다.
`master-numeric-contract.md#8`의 셀 유형 목록에서 `shrine`은 앵커 유형으로 읽는다.

### 2.4 보스 셀 배치 — 중앙열 스폰 금지 (검산으로 발견)

보스 셀은 스폰 셀의 **대각 반대편**이다. 그러나 3 × 2 그리드에서 중앙열(열 1)의 대각
반대편은 같은 열의 반대 행이다:

| 스폰 셀 | 대각 반대 | 중심 간 거리 | 시간 | 유효? |
|---|---|---|---|---|
| A (0,0) | F (2,1) | 17088 | 4.17 s | 유효 |
| C (2,0) | D (0,1) | 17088 | 4.17 s | 유효 |
| D (0,1) | C (2,0) | 17088 | 4.17 s | 유효 |
| F (2,1) | A (0,0) | 17088 | 4.17 s | 유효 |
| B (1,0) | E (1,1) | **6000** | **1.46 s** | **무효 — 같은 열** |
| E (1,1) | B (1,0) | **6000** | **1.46 s** | **무효** |

**규칙: 스폰 셀은 항상 모서리 셀(A/C/D/F)에서 고른다.** 중앙열(B/E)은 스폰 셀이 될 수
없다. 이 제약이 없으면 이동이 1.46 s로 줄어 "가로질렀다"는 감각이 사라진다.

시드는 4개 모서리 중 하나를 고르므로 스폰–보스 축은 4가지다.

### 2.5 앵커 좌표 정의

스폰·보스 앵커는 **셀 중심**에 둔다.

```
spawnAnchor = center(spawnCell)
bossAnchor  = center(bossCell)
```

**외곽 코너 앵커(여백 1200 기준 23637 / 5.77 s)를 쓰지 않는 이유:** 거리는 38% 늘지만
전투 개시 지점이 벽 두 면에 붙는다. 카메라가 벽 밖을 담고, 초기 대시 회피 방향이 8옥탄트
중 3개로 줄어 §6 검증 8번(이동 가능 방향 ≥ 3)의 경계에 걸린다. 셀 중심은 사방 여유가
동일하고 카메라 프레이밍이 안정적이다.

### 2.6 연결부

- 인접 셀 사이 연결부 **최소 폭 3000**. 대시 거리 2600 + 여유 400.
- 연결부는 셀 높이 6000 안에 들어간다(3000 ≤ 6000). 성립.
- 여유 400은 대시가 연결부 벽에 정확히 붙지 않아도 통과하도록 보장한다.
- 연결부는 항상 **직선**이다. 굽은 통로는 카메라 시야선을 끊어 위협 가시성을 해친다.

## 3. 레이어 분리

독립적으로 테스트 가능한 5개 레이어를 유지한다.

| # | 레이어 | 소유 | 타 레이어와 공유 |
|---|---|---|---|
| 1 | authored 셀 데이터 | 셀 유형, 모듈 ID, 앵커 ID, 시드 | 안정 ID + 트랜스폼 |
| 2 | 시각 지오메트리·비보행 장식 | 메시, 머티리얼, `visualElevation` | ID + 트랜스폼만 |
| 3 | 단순화 충돌 | 보행 불가 볼륨 (평면) | ID + 트랜스폼만 |
| 4 | 평면 내비게이션 | 이동 가능 영역, 클리어런스 | ID + 트랜스폼만 |
| 5 | 인카운터 존 | 스폰·목표·픽업·출구·리셋 앵커 | ID + 트랜스폼만 |

**금지:** 장식으로부터 충돌·내비게이션·인카운터 경계를 **추론하지 않는다.** 각 레이어는
자기 데이터를 갖는다. 메시 바운딩 박스로 충돌을 만드는 경로는 없다.

**허용:** 레이어 간 안정 ID와 트랜스폼 공유. 같은 랜드마크가 레이어 2에 메시, 레이어 3에
충돌 원기둥, 레이어 5에 인카운터 앵커를 각각 가질 수 있고 셋은 같은 ID 접두사를 쓴다.

## 4. 모듈 팔레트

### 4.1 팔레트 규모

| 셀 유형 | 모듈 수 | 셀당 배치 |
|---|---|---|
| `arena` | 8 | 3 |
| `transit` | 6 | 2 |
| `boss` | 4 | 1 |

### 4.2 모듈 기여 유형

| 기여 | 의미 | 게임플레이 효과 |
|---|---|---|
| `cover` | 엄폐 | `ranged` 투사체 차단, 회피 경로 제공 |
| `funnel` | 깔때기 | 적 진입을 좁혀 `LIGHT_3` 광역 가치를 올림 |
| `landmark` | 지표 | 방향 감각, 시각적 기억점 |
| `hazard` | 위험 | 지속 피해 장판 (대시 무적으로 무시 불가) |
| `sightline-break` | 시야 차단 | 전장 분할 — 단, 위협 은닉 금지(§6) |

`arena` 팔레트는 `cover`/`funnel`/`hazard`를 섞고, `transit`은 `landmark`/`cover`,
`boss`는 `landmark`만 쓴다. **보스 셀에 `sightline-break`를 두지 않는다** — 패턴 예고
데칼이 가려지면 회피 불가가 된다.

### 4.3 결정론적 선택과 변환

```
rng   = mulberry32(cellSeed)
picks = weightedSampleWithoutReplacement(palette, count, rng)

for each pick:
  rotation = rng.pick([0, 90, 180, 270])   // 90° 단위만
  mirrored = rng.bool()
  slot     = cellSlotFor(index)            // 셀 내 고정 슬롯
```

- 회전은 **90° 단위만**. 임의 각도는 부동소수 재현성 위험을 키우고 연결부 폭 보장을 깬다.
- 슬롯은 셀 내 고정 좌표다. 자유 배치는 연결부 클리어런스를 보장할 수 없다.
- 같은 모듈이 한 셀에 두 번 나오지 않는다(비복원 추출).

## 5. 시드 결정론

### 5.1 시드 구성

```
stageSeed = fnv1a32(`${stageId}|${campaignSeed}|${sortieIndex}`)
cellSeed  = fnv1a32(`${stageSeed}|${cellCol},${cellRow}`)
```

**FNV-1a 32비트를 쓰는 이유:** 구현이 20줄 미만, 부동소수 미사용, JS `>>> 0`로 32비트 정수
연산이 명확하다. 암호학적 성질은 필요 없다.

PRNG는 **mulberry32** — 상태 32비트, 정수 연산, 엔진 간 재현성이 확인된 구현.
`Math.random()`은 시드를 받지 않으므로 **사용 금지**.

### 5.2 기록과 재현

- `stageSeed`, `campaignSeed`, `sortieIndex`를 **런 스냅샷에 기록**한다.
- 같은 세 값 → 같은 레이아웃. 생성은 런 시작 시 **1회만** 실행한다.
- 생성된 레이아웃은 시뮬레이션 상태의 일부이며 `getRunDigest()` 입력에 포함된다.
- **런 도중 재생성 금지.** 렌더러 재마운트·해상도 변경·품질 티어 변경이 레이아웃을
  바꾸지 않는다.

### 5.3 저장·복원

| 상황 | 동작 |
|---|---|
| 런 중 저장 | 세 시드값 + `layoutVersion` + 레이아웃 해시 + 현재 tick + 개체 상태 |
| 복원 | 시드로 레이아웃을 **재생성**하고 개체 상태를 덮어씌운다 |
| 레이아웃 자체 저장 | 하지 않는다 — 시드 재생성이 정본 |
| 해시 불일치 | 생성 알고리즘이 바뀐 것. §5.4 |

### 5.4 `layoutVersion` 불일치 처리

생성 알고리즘이 바뀌면 같은 시드가 다른 맵을 낸다. 저장 시 기록한 레이아웃 해시와 복원 시
재생성 해시를 비교해:

| 결과 | 처리 |
|---|---|
| 일치 | 정상 복원 |
| 불일치 + 같은 `layoutVersion` | 버그. 복원 중단, 진단 로그 |
| 불일치 + 다른 `layoutVersion` | 사용자 고지 후 스테이지 재시작 |

레이아웃 스냅샷 폴백은 두지 않는다. 저장 용량과 마이그레이션 복잡도가 이득을 넘으며,
스테이지가 5–8분이라 진행 중 런 1회 손실이 허용 가능하다.

## 6. 가독성 보장

생성된 모든 레이아웃은 플레이 전 검증을 통과해야 한다. 실패 시 **시드를 증분해 재생성**
(최대 8회, 초과 시 authored 폴백 레이아웃).

### 6.1 검증 단언 목록

| # | 단언 | 임계 |
|---|---|---|
| 1 | 모든 인접 셀 연결부 폭 | ≥ 3000 |
| 2 | 스폰 셀이 모서리(A/C/D/F) | 필수 |
| 3 | 보스 셀 = 스폰 셀 대각 반대편 | 필수 |
| 4 | 스폰 앵커 → 보스 앵커 중심 거리 | = 17088 (허용 오차 1) |
| 5 | 스폰 → 보스 경로 존재 | 필수 |
| 6 | 모든 내비게이션 정점의 게임플레이 고도 | = 0 (허용 오차 0) |
| 7 | 보행 경사 | 0건 |
| 8 | 인카운터 앵커가 자기 셀 경계 안 | 필수 |
| 9 | 지휘관 반경 2600 안 이동 가능 방향 | ≥ 3 옥탄트 |
| 10 | 모듈이 연결부를 침범하지 않음 | 필수 |
| 11 | `hazard`가 연결부를 완전 봉쇄하지 않음 | 우회 경로 ≥ 1 |
| 12 | 보스 셀 내 `sightline-break` 모듈 | 0건 |
| 13 | 보스 패턴 최대 데칼이 보스 셀 안에 수납 | `arena-close` 기준 |
| 14 | 각 셀 출구가 진입 전에 보임 | 시야선 검사 |
| 15 | 픽업·목표 앵커가 장식에 가려지지 않음 | 시야선 검사 |
| 16 | 셀 재진입 시 인카운터 재트리거 | 0건 |
| 17 | `shrine` 앵커가 `transit` 셀에만 존재 | 필수 |
| 18 | 소프트락 경로 | 0건 (모든 셀에서 스폰 셀 도달 가능) |
| 19 | 적 추적이 무관한 셀을 관통 | 0건 (셀 경계 리쉬) |

### 6.2 시야선 검사 정의

"보인다"는 최소 보장 가시 반경 **3000**(`encounter-wave-spec.md#4.4`의
`VISIBILITY_RADIUS`, 근거는 `camera-vfx-direction.md#2.2`의 렌더러 좌표계 실측) 안에서
비보행 장식에 가려지지 않음을 뜻한다. 검사는 셀 진입 앵커에서 대상 앵커로 광선을 쏘아
레이어 2 장식과의 교차를 본다.

**셀 대각선이 10000인데 가시 반경은 3000이다.** 즉 한 셀도 전부 보이지 않는다. 이것이
§8.1의 "시야선" 항목을 제약한다 — 셀 경계 너머를 미리 보는 것은 **랜드마크 실루엣**으로만
가능하며(높은 장식은 가시 반경과 무관하게 원경에 보임), 위협 개체는 3000 안에 들어와야
보인다. 따라서 셀 진입 앵커에서 **출구·목표 앵커까지 거리가 3000을 넘으면** 중간에
시야 유도 랜드마크를 배치해야 한다(검증 14번).

## 7. 조명 동기 부여

모든 로컬 광원은 **보이는 발광체**에 부착된다.

### 7.1 광원 인벤토리 스키마

| 필드 | 의미 |
|---|---|
| `emitterId` | 발광체 오브젝트 ID (레이어 2) |
| `lightId` | 광원 ID |
| `attachment` | 발광체 로컬 트랜스폼 |
| `type` | `point` / `spot` |
| `range` | 도달 거리 |
| `color`, `intensity` | 색·강도 |
| `occlusionIntent` | 그림자 생성 여부와 의도 |
| `enabled` | 현재 활성 상태 |
| `fallback` | 발광체 소실 시 동작 |

### 7.2 규칙

- **설명되지 않는 부유 광원 금지.** `emitterId`가 없는 로컬 광원은 검증 실패다.
- 발광체가 이동하면 광원도 이동한다(부착 트랜스폼 유지).
- 발광체가 비활성·은닉·파괴·언로드되면 로컬 기여를 **제거**한다.
- 앰비언트·월드 조명은 **별도 문서화**한다. 전역 가시성과 분위기 목적으로만 쓰며,
  횃불 같은 로컬 광원을 흉내 내는 데 쓰지 않는다.

### 7.3 PCG와 조명

모듈은 자기 발광체와 광원을 **쌍으로** 갖고 온다. 생성기가 광원만 배치하는 경로는 없다.
셀당 로컬 광원 상한 **6** — 초과 시 가장 먼 것부터 비활성화한다
(성능 예산 `master-numeric-contract.md#9`).

## 8. "오픈월드 느낌"의 정의

24000 × 12000 유계 아레나에서 이 표현이 **의미하는 것**과 **의미하지 않는 것**을 못박는다.

### 8.1 의미하는 것

| 요소 | 구현 |
|---|---|
| 시야선 | 위협은 반경 3000 안에서 보이고, 셀 너머는 랜드마크 실루엣으로 예감한다 |
| 경로 선택 | 스폰 → 보스 사이 최소 2개 경로. 어느 `arena`를 먼저 칠지 고른다 |
| 비선형 셀 순서 | `transit` 셀은 양방향. 되돌아갈 수 있다 |
| 랜드마크 방향 감각 | 각 셀에 고유 `landmark` 1개. 미니맵 없이 위치를 안다 |
| 시드별 변주 | 같은 스테이지도 출정마다 다른 배치 |
| 횡단 감각 | 스폰 → 보스 17088 (4.17 s), 경유 시 더 김 |

### 8.2 의미하지 않는 것 (명시적 배제)

- **스트리밍 없음.** 전 셀이 런 시작 시 로드된다. 24000 × 12000은 한 번에 담긴다.
- **스테이지 간 연속 월드 없음.** 각 스테이지는 독립 아레나다.
- **수직 이동 없음.** §1 평면 규칙이 최우선이다.
- **자유 탐험 없음.** 페이즈 타임라인(`master#2`)이 진행을 몰아간다. 셀을 둘러볼 시간은
  `DESCENT` 30초뿐이다.
- **절차적 서사 없음.** 스토리는 authored이며 `lobby-story-presentation-spec.md`가 소유한다.

**정직한 요약:** 이것은 오픈월드가 아니라 **오픈월드의 공간 감각을 빌린 유계 아레나**다.
플레이어가 얻는 것은 탐험이 아니라 *경로 선택과 방향 감각*이다.
