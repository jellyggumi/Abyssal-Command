# 잿불 법정 전투 타격감(VFX) 수정 제안

대상: 루트 라우트 `sprite-2-5d.js` (2.5D 스프라이트 아레나). 상태: **제안 — 승인 대기, 코드 미변경.**
근거 조사: `.survey/vfx-combat-feel-cinder-court/`. 경계: `CLAUDE.md §2`, `tests/sprite-2-5d-browser.cjs`.

## 0. 문제 한 줄
현재 전투 피드백은 **얇은 canvas 타원/호 stroke 한 겹**이 전부다(피격 플래시·공격 아크·노바 링·워드 오라). 타격 순간에 여러 감각이 동시에 터지지 않아 "게임스럽지 못한" 느낌의 실체는 **레이어링과 무게의 부재**다.

## 1. 결정론 안전성 근거 (왜 이 라우트에선 마음껏 넣어도 되는가)
- 스폰은 `waveSeed + nextEnemyId*3` 결정적 인덱싱, **RNG 호출 없음**. `sprite-2-5d.js:808`
- digest는 런 종료 시 `{wave, score, kills, relics}` **요약만** 저장. 프레임/틱 상태 미저장. `sprite-2-5d.js:698-713`
- 따라서 히트스톱(틱 스킵)·화면 흔들림·파티클은 **최종 결과에 영향 없음** → 캠페인 라우트의 시뮬-digest 제약이 여기엔 적용되지 않는다.
- 단 계약 테스트 `readRenderSnapshot()`의 `hitFlash`/`shadow`/`healthBar` 키·깊이비율은 유지. 신규 이펙트는 **additive 확장**(새 함수·새 스크래치)으로.

## 2. 우선순위별 수정안 (조사 빈도순 = 타격감 기여순)

### P1 — 히트스톱 (무게의 1순위)
- **지금:** 없음. 공격이 적을 "통과"하는 느낌.
- **바꿀 것:** 전역 `state.hitStopTicks` 카운터. `frame()`의 catch-up 루프에서 `hitStopTicks>0`이면 `fixedUpdate` 스킵하고 카운터만 감소(렌더는 계속). `sprite-2-5d.js:1586-1590` 진입부.
- **수치[TARGET]:** 라이트 히트 2틱(≈33ms) · 노바/처치 5틱(≈83ms). 감소된 모션 시 0.
- **발화 지점:** `damageEnemy()`(`:838`), `castNova()`(`:618`).

### P2 — 스프라이트 실루엣 플래시 (닿음 확정)
- **지금:** 액터 위 타원 외곽선 1개(`#7ff6ff`/`#ff8a4c`). 스프라이트 자체는 안 변함. `:1233-1250`
- **바꿀 것:** 피격 스프라이트 픽셀만 **흰→색조로 틴트**. 첫 2프레임 강한 흰색(alpha≈0.85) → 색조 감쇠. 기존 타원은 얇은 보강 링으로 격하/제거.
- **⚠ 구현 함정(목업에서 실측 확인):** `source-atop` fillRect를 **메인 캔버스에 직접** 쓰면 안 됨 — 백드롭 픽셀이 bbox 전역에 있어 스프라이트 주변에 **흰 사각형**이 찍힌다. 반드시 **오프스크린 캔버스**에 스프라이트를 그리고 거기서 `source-atop` 틴트 후, 결과를 메인에 `drawImage`. 목업 `mockup.html`의 `drawActor`가 검증된 참조 구현.
- **계약:** `hitFlash` 스냅샷 키는 유지(테스트 통과). 실루엣 틴트는 draw-only라 스냅샷에 안 나타남.

### P3 — 화면 흔들림 (힘 전달)
- **지금:** 없음.
- **바꿀 것:** `state.shakeTime`/`shakeAmp`. `render()` 진입 시 base transform 위에 `save()→translate(dx,dy)→…→restore()`. `dx,dy`는 감쇠 사인/노이즈. `sprite-2-5d.js:1465` 직후 래핑.
- **수치[TARGET]:** 라이트 히트 진폭 3px·0.12s · 노바 10px·0.25s · 처치 5px·0.15s. 감소된 모션 시 진폭 0.

### P4 — 불티 파티클 버스트 (스펙터클의 몸통)
- **지금:** 없음.
- **바꿀 것:** 고정 상한 파티클 풀(예 64). 렌더 순서: 액터 → `globalCompositeOperation='lighter'`로 파티클 일괄 → `source-over` 복귀(배칭). 정수 좌표. 다크판타지 청록/주황 팔레트에 **불티(ember spark)**가 팔레트상 완벽.
- **매핑:** 피격=주황 불티 6~10 · 노바=방사형 대량 · 처치=파편 폭발 + 잔불. 감소된 모션 시 개수 대폭 축소 또는 정적 1프레임.

### P5 — 렌더 전용 넉백 (물리 반응)
- **지금:** 시뮬·렌더 둘 다 없음. 적이 맞아도 계속 전진.
- **바꿀 것:** 캠페인의 `IMPACT_KNOCKBACK`(render-space offset, 매 프레임 권위 위치 복귀) 패턴 이식. 시뮬 위치 불변 → digest 무관. `enemy.knockback{dx,dy,t}` 렌더 오프셋만.
- **수치[TARGET]:** 라이트 8px·0.16s. 접촉 축(player→enemy) 방향.

### P6 — 슬래시 트레일 (궤적)
- **지금:** 정적 호 stroke 1개(프레임 2~3만). `:1268-1296`
- **바꿀 것:** 공격 프레임 동안 facing 방향으로 스윕하는 **초승달 트레일**(그라디언트 알파 폴리곤/여러 겹 호). 기존 아크를 대체.

### P7 — 데미지 넘버 (선택, 성장 정보)
- **지금:** 없음. HP 바 감소로만 유추.
- **바꿀 것:** 경량 텍스트 파티클(상승+페이드). 노바 다중 히트 시 숫자 폭포 → 파워 판타지. **가독성 우려로 옵션 처리** — on/off 결정 필요.

### P8 — 처치 스펙터클 (레이어링)
- **지금:** 단순 `fadeTime` 페이드아웃. `:847-859`
- **바꿀 것:** 처치 순간 P4 파편 폭발 + P3 미세 셰이크 + P1 히트스톱을 **동시 발화**. 사망을 보상으로 전환.

## 3. 스킬별 전용 개선
- **노바(`castNova`/`drawNovaBurst`):** 단일 링 → 코어 섬광 + 다중 충격파 링 + 방사 불티 + 강한 셰이크 + 히트스톱. AoE의 "작렬"을 실제로 보이게.
- **워드(`castWard`/`drawWardAura`):** 정적 타원 → 회전 룬/펄스 + 피격 굴절 플래시(피해 거부 순간 청록 번쩍). 실드가 "살아있게".

## 4. 레이어링 규칙 (핵심 통찰)
한 타격 = **소리 + 스프라이트 플래시 + 불티 + 히트스톱 + 미세 셰이크**를 동시 발화. 개별 기법을 흩뿌리지 말고 이벤트별 "강도 언어"로 묶는다: 라이트 히트 < 노바 < 처치.

## 5. 접근성·성능 가드 (필수)
- `prefers-reduced-motion`: 흔들림 진폭 0, 히트스톱 0~1틱, 파티clot 최소, 강한 플래시→약한 정적 표시. 기존 `state.reducedMotion` 분기 재사용.
- 파티clot 상한 고정 + `'lighter'` 배칭 + 정수 좌표로 60Hz p95 프레임 예산 유지.
- 히트스톱은 렌더 루프에만, UI/오디오 타이밍 미오염(국소 정지).

## 6. 검증 계획 (구현 시)
- `node --test 'tests/**/*.test.mjs'` 및 `tests/sprite-2-5d-browser.cjs` 계약 유지 확인(스냅샷 키·깊이비율 불변).
- 프레임 계측: 다수 적 + 노바 동시 히트에서 p95 프레임 시간 실측 → 파티클 상한 확정([TARGET]→[OBSERVED]).
- 사람 플레이 판정: "때렸을 때 무게가 느껴지는가" 정성 확인.

## 7. 승인 필요 결정
1. **적용 범위:** P1~P6 전량 vs 최소 세트(P1 히트스톱 + P2 플래시 + P4 불티)만 먼저?
2. **데미지 넘버(P7):** 넣을지 / 옵션 토글로 둘지 / 뺄지.
3. **기존 타원 처리:** 피격 타원을 제거할지, 실루엣 플래시와 병행할지.
4. **스킬 리워크 깊이:** 노바/워드를 이번에 함께 갈지, 근접 타격감 먼저 잡고 후속으로 뺄지.

## 8. 시각화 (before/after 목업)
실제 백드롭 + 실제 워든/코호트 스프라이트 시트로 게임 렌더 로직(깊이 스케일·pivot·그림자)을 그대로 복제해 렌더한 목업. AI 생성이 아니라 실제 좌표·팔레트 기반이라 구현 결과에 가깝다. `_workspace/current/design/vfx-mockups/`:
- `melee-before.png` / `melee-after.png` — 근접 타격: 얇은 stroke 한 겹 → 실루엣 플래시+불티+초승달 트레일+넉백+데미지"58"+미세 셰이크.
- `nova-before.png` / `nova-after.png` — 노바 AoE: 타원 링 1개 → 코어 섬광+3중 충격파+방사 불티+전체 실루엣 플래시+강한 셰이크.
- `mockup.html` — 위 4장을 그린 소스. `drawActor`의 오프스크린 실루엣 플래시가 §P2의 검증된 참조 구현.

> 목업 자산 생성 편차: `CLAUDE.md §3`은 개념 이미지에 god-tibo-imagen을 지정하나, 이 세션에서 `gti`가 이 계정의 Codex 백엔드에서 전 모델(`gpt-5.4`/`gpt-5.1`/`gpt-5`) "not supported" 400으로 작동 불능이었고 내장 이미지 도구도 404였다. 그래서 실제 게임 자산을 캔버스로 렌더+브라우저 캡처하는 방식으로 대체했다 — 오히려 실제 좌표·팔레트에 더 충실하고 런타임 자산이 아닌 논의용 목업이다.
