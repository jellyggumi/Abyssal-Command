## 1. 정보 우선순위

읽는 데 걸려도 되는 시간으로 등급을 나눈다. 등급이 배치를 결정한다.

| 등급 | 허용 인지 시간 | 항목 | 배치 |
|---|---|---|---|
| **즉시** | <100 ms (주변시) | 예고 위험 영역, 지휘관 위치, 대시 충전 | **월드 공간** (HUD 아님) |
| **즉시** | <100 ms | 지휘관 내구도 | 캐릭터 발밑 링 |
| **일별** | <300 ms (한 번 흘끗) | 스킬 쿨다운, 콤보 단계, 보스 HP·페이즈 | 화면 가장자리 |
| **일별** | <300 ms | 웨이브 경고, 페이즈 진행 | 상단 얇은 띠 |
| **요청 시** | 수 초 | 스킬 상세, 통계, 로드아웃 | 일시정지 패널 |
| **런 종료 후** | 무관 | 획득 Shard, XP, 결과 | 결과 화면 |

**핵심 판단:** 즉시 등급은 **HUD가 아니라 월드에 그린다.** 예고 데칼은 지면에, 내구도는
캐릭터 발밑 링에 붙인다. 주변시로 읽히는 위치는 화면 가장자리가 아니라 **시선이 이미
가 있는 곳** — 즉 캐릭터 주변이다.

**HUD에 두지 않는 것:** 미니맵(셀 랜드마크가 대체, `pcg#8.1`), 적 개체 수, DPS 미터,
좌표, 획득 Shard 실시간 카운터(런 종료 후 일괄).

전장은 full-bleed 캔버스라는 기존 계약 `[OBSERVED]` (`README.md`, `docs/…design.md`)를
유지한다. 중앙 패널은 어떤 경우에도 두지 않는다.

## 2. 조작 레이아웃

### 2.1 문제 정의

이동 + `LIGHT` + `HEAVY` + `DASH` + 스킬 6 = **접점 후보 10개.** 390 × 844 화면에서
엄지 도달 반경은 약 176 px다. 10개를 상시 노출하면 전장이 사라진다.

### 2.2 해소 — 액티브 스킬만 버튼을 갖는다

`skill-and-growth-spec.md#2`의 20종 중 패시브가 6종이다.

| 카테고리 | 액티브 | 패시브 | 슬롯 |
|---|---|---|---|
| `melee-amp` | 3 | 2 | 2 |
| `aoe-burst` | 5 | 0 | 2 |
| `mobility` | 2 | 3 | 1 |
| `sustain` | 4 | 1 | 1 |

| 로드아웃 구성 | 필요 버튼 |
|---|---|
| 최악 (전부 액티브) | 6 |
| 전형 (`melee-amp` 1패시브 + `mobility` 패시브) | **4** |
| 최선 | 3 |

**설계:** 액티브 슬롯 **4개를 상시 노출**하고, 5–6번째는 **확장 팔레트**로 접는다.
전형 로드아웃은 확장을 열 일이 없다.

### 2.3 세로 (390 × 844)

안전 영역: 상단 47, 하단 34. 사용 가능 높이 763 (90.4%).

| 요소 | 위치 (뷰포트 %) | 크기 | 비고 |
|---|---|---|---|
| 이동 스틱 | 중심 (25%, 84.5%) | 반경 68 px | 좌하, 가상 스틱 (터치 지점에 생성) |
| `LIGHT` | 중심 (79%, 88%) | 지름 72 px | 우하, 가장 큼 — 최빈 입력 |
| `HEAVY` | 중심 (64%, 90%) | 지름 56 px | `LIGHT` 좌하 |
| `DASH` | 중심 (89%, 77%) | 지름 60 px | `LIGHT` 우상, 충전 2개 표시 |
| 스킬 1–2 | (57%, 76%) / (70%, 70%) | 지름 52 px | 동사 클러스터 상단 호 |
| 스킬 3–4 | (83%, 64%) / (93%, 56%) | 지름 52 px | 계속 호 |
| 확장 토글 | (95%, 44%) | 지름 40 px | 5–6번 있을 때만 표시 |
| 지휘관 내구 | 캐릭터 발밑 | 링 | 월드 공간 |
| 콤보 단계 | (50%, 72%) | 높이 6 px | 캐릭터 위 얇은 3점 |
| 보스 HP | (50%, 8%) | 폭 80% | 상단, 70/40% 눈금 |
| 페이즈 진행 | (50%, 3%) | 높이 4 px | 최상단 얇은 띠 |
| 웨이브 경고 | 화면 가장자리 | 방향 화살 | 스폰 방향 |

동사 클러스터는 우하단에서 **시계 반대 방향 호**로 펼친다. 엄지 회전 궤적과 일치한다.

### 2.4 가로 (844 × 390)

안전 영역 높이 309 (79.2%) — 세로보다 좁다. 수직 배치를 줄인다.

| 요소 | 위치 (뷰포트 %) | 비고 |
|---|---|---|
| 이동 스틱 | (11.5%, 66.5%) | 좌단으로 이동 |
| `LIGHT` | (91%, 72%) | 우단 |
| `HEAVY` | (82%, 82%) | |
| `DASH` | (95%, 55%) | |
| 스킬 1–4 | (75%, 60%) → (88%, 38%) | 더 조밀한 호 |
| 보스 HP | (50%, 6%) | 폭 60% (가로에서 80%는 과함) |
| 콤보 | (50%, 80%) | 캐릭터 아래로 |

`[OBSERVED]` 현재 빌드는 fullscreen + landscape lock을 자동 요청하고, 잠금 실패 시
회전 안내 없이 **시계 방향 논리 가로를 세로 뷰포트에 투영**한다 (`README.md`,
`docs/abyssal-command-defense-survivor-design.md`). 이 동작을 유지하므로 세로 레이아웃은
**논리 가로가 실패한 경우의 폴백**이다. 두 레이아웃 모두 검증한다(§8).

### 2.5 버튼 상태 표현

| 상태 | 시각 | 비색 채널 |
|---|---|---|
| 사용 가능 | 채워진 원 + 아이콘 | — |
| 쿨다운 | 원형 스윕 게이지 | 남은 초 숫자 |
| 홀드 중 | 외곽선 확대 | 진동 (지원 시) |
| 버퍼됨 | 외곽선 점멸 1회 | — |
| 사용 불가 (자원) | 40% 알파 | 사선 빗금 |
| 미장착 | 렌더 안 함 | — |

`DASH` 충전은 버튼 위 **점 2개**로 표시한다. 숫자보다 빠르게 읽힌다.

## 3. 전투 상태 표시

| 항목 | 배치 | 시각 인코딩 | 비색 중복 채널 |
|---|---|---|---|
| 지휘관 내구 | 캐릭터 발밑 링 | 링 채움 비율 | 25% 이하 시 링 두께 ×2 + 비네트 |
| 대시 충전 | `DASH` 버튼 위 | 점 2개 채움 | 재생 중 점이 원호로 차오름 |
| 스킬 쿨다운 | 각 버튼 | 원형 스윕 | 남은 초 숫자 |
| 콤보 단계 | 캐릭터 위 | 점 3개 (1/2/3 채움) | 단계별 점 크기 증가 |
| 콤보 창 만료 | 콤보 점 | 마지막 점 축소 애니 | 축소 = 남은 시간 |
| 보스 HP | 상단 바 | 채움 + 70/40% 눈금선 | 페이즈 숫자 라벨 `P1/P2/P3` |
| 보스 페이즈 전환 | 상단 바 | 백색 확산 | 페이즈 라벨 변경 |
| 웨이브 경고 | 화면 가장자리 | 주황 화살 | 카운트다운 숫자 |
| 페이즈 진행 | 최상단 띠 | 6분할 진행 | 현재 페이즈명 텍스트 |

**내구도를 화면 구석이 아니라 발밑에 두는 이유:** `BIGWAVE` 밀도에서 시선은 캐릭터에
고정된다. 구석 게이지는 위험할 때 정확히 읽히지 않는다. 발밑 링은 주변시로 잡힌다.

## 4. 보스 패턴 경고에서 HUD의 역할

`master-numeric-contract.md#6`은 **월드 공간 데칼이 1차 예고**이며 HUD 텍스트 단독 예고를
금지한다.

### 4.1 HUD가 하는 것

| 역할 | 구현 | 조건 |
|---|---|---|
| 화면 밖 예고 방향 지시 | 가장자리 화살 + 거리 | 데칼이 뷰포트 밖일 때만 |
| 패턴 이름 자막 | 하단 작은 텍스트, 0.8 s | **설정에서 기본 OFF** |
| 안전지대 방향 | `arena-close` 한정 가장자리 청색 화살 | 안전지대가 화면 밖일 때 |

### 4.2 HUD가 하지 않는 것

- 데칼을 **대체**하지 않는다. 데칼 없이 HUD만 뜨는 경로는 없다.
- 데칼을 **복제**하지 않는다. 화면 안에 데칼이 보이면 HUD 화살을 띄우지 않는다.
- 카운트다운 숫자를 띄우지 않는다. 데칼의 채움 진행이 그 정보다.

**패턴 이름 자막이 기본 OFF인 이유:** 텍스트를 읽는 것은 데칼을 보는 것보다 느리다.
텍스트에 의존하는 습관이 생기면 자막이 없는 상황에서 회피율이 떨어진다. 학습 보조로만
제공한다.

## 5. 성장 선택 UI

### 5.1 런 중 성장 제안 (3회 / 스테이지)

| 항목 | 규칙 |
|---|---|
| 표시 | 전투 일시정지 + 카드 3장 |
| 배치 | 가로 3분할, 카드당 최소 높이 120 px |
| 선택 | 탭 1회 (드래그 없음) |
| 취소 | 없음 — 반드시 하나 선택 |
| 시간 제한 | 없음 |
| 정보 | 이름 / 1줄 효과 / 카테고리 색 띠 |

카드에 긴 설명을 넣지 않는다. 이름 + 1줄이면 충분하며, 길면 읽지 않는다.

### 5.2 로비 로드아웃 편집기

| 항목 | 규칙 |
|---|---|
| 배치 | 좌측 독 `성장` 탭 (기존 사이드독 유지 `[OBSERVED]`) |
| 슬롯 표시 | 카테고리별 그룹 — `melee-amp` 2, `aoe-burst` 2, `mobility` 1, `sustain` 1 |
| 장착 방식 | **탭 → 탭** (슬롯 선택 후 스킬 선택). 드래그 대안 필수 |
| 드래그 | 데스크톱에서만 보조 제공 |
| 상한 위반 | **선택 불가 상태로 미리 표시** — 커밋 후 거부하지 않는다 |
| 미해금 | 회색 + 자물쇠 + 해금 조건 1줄 |
| 레벨업 | 스킬 상세에서 Shard 잔액과 다음 레벨 비용 표시 |

**상한 위반을 커밋 전에 차단하는 이유:** `melee-amp` 슬롯이 2/2일 때 세 번째를 탭하면
"어느 것과 교체할까요"를 묻는다. 거부 메시지를 띄우지 않는다 — 거부는 사용자가 이미 한
행동을 무효화하는 것이고, 교체 제안은 의도를 완성시킨다.

## 6. 심플함 예산

"심플하지만 정보전달이 명확"을 숫자로 못박는다.

| 지표 | 상한 | 근거 |
|---|---|---|
| 동시 HUD 요소 | **9** | 이동1 + 동사3 + 스킬4 + 보스바1 |
| `BIGWAVE` 중 화면 텍스트 글자 수 | **12** | 쿨다운 숫자 4×2 + 페이즈명 4 |
| HUD가 덮는 화면 면적 | **≤18%** | 나머지 82%는 전장 |
| 동시 애니메이션 HUD 요소 | **3** | 쿨다운 스윕만 |
| 색상 수 (HUD) | **5** | `camera-vfx-direction.md#6` 팔레트 부분집합 |
| 폰트 크기 종류 | **3** | 숫자 / 라벨 / 카드 제목 |

### 6.1 무엇을 잘라냈고 왜

| 잘라낸 것 | 사유 (§1 우선순위 대조) |
|---|---|
| 미니맵 | 셀 랜드마크가 방향 감각을 제공(`pcg#8.1`). 즉시 등급이 아님 |
| 적 개체 수 카운터 | 밀도는 화면으로 보인다. 숫자는 요청 시 등급 |
| 획득 Shard 실시간 | 런 종료 후 등급. 전투 중 알 필요 없음 |
| XP 바 | 런 종료 후 등급 |
| 스킬 이름 라벨 | 아이콘 + 카테고리 색으로 충분. 글자 수 예산 초과 |
| 데미지 숫자 | **선택 설정, 기본 OFF.** `BIGWAVE`에서 초당 4.2 처치 × 숫자는 화면을 덮는다 |
| 동료 상태 패널 | 동료는 자동 전투(`skill-and-growth-spec.md#6.2`). 개입 불가면 표시 불필요 |
| 스탠스 전환 UI | 시스템 자체가 폐기됨(`skill-and-growth-spec.md#6.1`) |

### 6.2 자동 숨김

| 요소 | 숨김 조건 | 복귀 조건 |
|---|---|---|
| 확장 스킬 팔레트 | 3초 무조작 | 토글 탭 |
| 보스 HP 바 | 보스 없음 | 보스 스폰 |
| 웨이브 경고 | 스폰 완료 | 다음 웨이브 3초 전 |
| 페이즈 진행 띠 | 항상 표시 | — |
| 콤보 점 | 콤보 0 | 콤보 1 진입 |

## 7. 접근성

| 항목 | 기준 |
|---|---|
| 최소 터치 타겟 | 44 × 44 CSS px (스킬 52, 동사 56–72로 초과 충족) |
| 터치 타겟 간격 | ≥8 px |
| 텍스트 대비 | ≥4.5:1 |
| 비텍스트 대비 (게이지·아이콘) | ≥3:1 |
| 색 비의존 | §3 전 항목에 비색 채널 존재 |
| reduced-motion | 쿨다운 스윕 → 단계 채움, 점멸 제거 |
| 방향 전환 | 게임 상태·시뮬레이션 tick 보존, 레이아웃만 재계산 |
| 안전 영역 | 모든 컨트롤이 `env(safe-area-inset-*)` 밖 |
| 스크린 리더 | 로비 독·로드아웃·결과 화면에 `aria-label`. 전투 HUD는 `aria-hidden` |

**전투 HUD를 `aria-hidden`으로 두는 이유:** 초당 수십 회 변하는 값을 읽어주면 소음이다.
전투는 시각·청각 피드백(`build-game-audio-feedback` 영역)이 담당하고, 스크린 리더는
로비·결과·설정에서 완전 지원한다.

기존 접근성 기준선은 `_workspace/archive/20260727-lobby-dock-redesign/ui/accessibility-audit.md`
에 있다 `[INFERENCE — 파일 존재만 확인, 내용 미검토]`. 로비 독 구조를 유지하므로 그
기준선을 승계한다.
