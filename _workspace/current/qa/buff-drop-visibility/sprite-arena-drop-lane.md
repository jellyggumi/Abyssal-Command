# 2.5D 스프라이트 아레나 드랍 레인 — game-studio-harness (2번째 라인)

게임: `sprite-2-5d.js` (루트 `index.html`, 캠페인과 완전 별개 코드). 사용자가
"캠페인과 2D 스프라이트 아레나도" 대상 확정.

## 진단 [OBSERVED] — 실브라우저

라이브 구동(`http://127.0.0.1:8000/`)으로 확인:

- 드랍 시스템 자체는 **정상**: 모든 처치가 pickup 생성(100%, `spawnPickup` @death),
  필드에 다이아몬드로 렌더(스크린샷 확인), 78px 밖이면 필드 잔존(즉시 흡수 아님).
- 그러나 **수집이 안 됨**: 근접 전투 구동 시 처치 5회에도 유물 0, 체력 100→65로
  하락(ember-shard 힐도 미회수). 드랍이 필드에 쌓이기만 함.

### 근본 원인 — 수집 반경이 공격 사거리보다 좁다

| 값 | 수치 | 근거 |
|---|---|---|
| 플레이어 공격 사거리 | 160 | `PLAYER_ATTACK_RANGE` |
| 적 공격 사거리 | 76 | `ENEMY_ATTACK_RANGE` |
| pickup 자석 반경(수정 전) | **78** | `PICKUP_MAGNET_RADIUS` |
| 자석 y축(iso 압축 `*1.42`) | ~55 | `updatePickups:625` |

플레이어가 최대 160px 거리의 적을 죽이면 드랍이 시체 위치(≤160px)에 생기는데,
수집 자석은 78px(세로 55px)라 **자기가 죽인 드랍이 자기 수집권 밖**에 떨어진다.
그래서 필드에 쌓이기만 하고 "안 떨어진다"로 느껴진다. 수집 코드(`updatePickups`
거리검사→`collectPickup`)는 정상 — 순수 튜닝 불일치.

## 수정 (designer 결정: 걸어가서 줍기 유지, 신뢰성 확보)

`PICKUP_MAGNET_RADIUS` **78 → 160** (= `PLAYER_ATTACK_RANGE`). 근접 처치 드랍은
수집권 안에 들어와 걸으면서 자연 수집. 원거리 Nova 처치(반경 250) 드랍은 여전히
160 밖이라 걸어가야 함 → walk-to 성격 유지, 전-아레나 vacuum 아님. 12초 수명 유지.

## 검증 [OBSERVED] — 동일 구동 스크립트 before/after

| | 수정 전(78) | 수정 후(160) |
|---|---|---|
| 근접 구동 수집(유물) | 0 | **2** |
| 힐 이벤트 | 0 | **1** |
| 처치 | — | 5 |
| 체력 추이 | 100→65 (미회수) | 100 유지(회수) |

스크린샷: 유물 2 HUD 확인. 결함 아님이 아니라, 튜닝으로 실제 수집이 안정화됨.

## 미결 (정직 고지)

- `PICKUP_MAGNET_RADIUS=160`은 `[TARGET]` — 손맛 미측정. 너무 넓으면 줄이면 됨.
- 스프라이트 아레나 브라우저 테스트(`tests/sprite-2-5d-browser.cjs`)에 pickup
  수집 커버리지 **0건**(grep 무결과). 회귀 가드는 후속 물리 단계 — 이 세션은
  라이브 before/after로 증명.
- 캠페인 변경(`defense-*`)은 이 레인과 무관, 그대로 유지.
