# Lobby Concept — Designer Position (출정 lobby)

*Independent position for the lobby-first redesign meeting. Grounded in `adoptable-pattern-shortlist.md` (A1–A6), `solutions.md`, `context.md`, `qa/benchmark-notes.md` + `vampire-survivors-stage-selection.jpg`, and the shipped `app.js` `renderSortieTabBody()` / `renderDockRight()` / `renderSortieFab()` / `renderIdleReturnToast()` + `idleReturnSummary()`. Concept/direction only — no code.*

## Position

The 출정 lobby should stop being a stage-picker-plus-spec-sheet and become the **war-room aperture onto the 심연**: the Dusk Warden stands at the 재의 봉쇄선 (Cinder Span blockade line) looking OUT into the encroaching dark, and the two docks are command instruments bolted to the rim of that view. The single most "form-like" element today — the `.briefing-panel`'s `<dl class="briefing-stats">` with its five 지형/위협/점유/랜드마크/보상 rows (app.js L800–806) — is exactly the "reads as a form, not a game" failure the survey names, and it must be demoted from a default spec-dump to a **threat-read that is reward-forward** (per Lane C: briefings are read only if ≤ a few seconds and carry actionable reward info). The live 3D canvas is not decoration — it is the **diegetic map**: selecting a stage changes what the aperture shows (the selected boss mesh + Cinder Span terrain tint already exist via `meshRootForStageBoss()` / `stageArtPath()`), so choosing a front is looking at the enemy, not reading a row. And idle-return — currently a silent balance bump in an 8s toast (`renderIdleReturnToast`) — becomes the loved "payday" (A1): re-entry opens on the accrued pile counting up over the live scene, then hands the player straight to the next sortie, arming "one more run" instead of leashing them with a login.

## Concrete lobby changes

- **Reframe the whole surface as a "front aperture," not a menu (A6 + benchmark Takeaway 6 "make the menu a place").** The center gap between the docks is the *view into the 심연*; the selected stage's scene (Cinder Warden mesh, ash/rift terrain) renders live through it. On stage-select the canvas re-tints/swaps its focus subject (reuse `meshRootForStageBoss(selected.id)` + `stagePresentationFor()` labels already fed to the briefing) so the world *is* the map — cheap opacity/transform + material-tint tween, no new shader. Ref: `vampire-survivors-stage-selection.jpg`, where the red map art bleeds behind every panel.

- **Turn the briefing `<dl>` from a spec sheet into a threat-read (A2 card-language, Lane C).** Default view = boss portrait (already `portraitMarkup(meshRootForStageBoss…)` at L799) + one threat line + one **"win this → 다음 보상"** reward chip (the `nextRewardName(selected.id)` value promoted from buried `<dt>다음 보상</dt>` to a headline). The four terrain stats (지형/고지, 위협/측면, 점유→추출, 랜드마크) collapse behind a **"전황 상세" progressive-disclosure toggle** — data preserved, clutter gone (constraint 4 "legibility over exposure / no currency-soup"). This is the "loadout theater not a form" pivot.

- **Give the stage rail illustrated-card verb economy (A2: `soulstone-survivors-levelup-cards.jpg`, `doodle-rpg-survivor-levelup.png`; center stage list in `vampire-survivors-stage-selection.jpg`).** Each `.stage-card` (L793) keeps its art but surfaces a **threat tag + a reward chip on the card face** and its state as a decision, not a label — so 출전 가능/CLEAR/잠김 read as node states, and the pick feels like choosing a target.

- **String the stage cards along a visible 봉쇄선 spine (A3 "shown MAP, not list"; pattern 8 stage map).** Instead of a plain vertical scroll (`.stage-rail`), connect the cards with a thin blockade-line connector + node dots (cleared = held, current = lit, locked = dark, next = pulsing) so "there is a lot of front here" reads at a glance — the A3 map treatment applied to stage-select. Pure CSS connector + dots, zero perf cost.

- **Surface a compact, read-only "current loadout" glance in the sortie panel (loadout-theater bridge; `vampire-survivors-stage-selection.jpg` left modifier/relic panel).** A one-row read of FRONT companions + key active traits that *this* sortie carries — sourced from the existing left-dock state, NOT relocated (constraint 5). It makes the lobby a loadout theater (what am I sending in) without rebuilding navigation; tapping it opens the relevant left dock.

- **Elevate 작전 개시 to the one charged, world-reactive commit CTA (pattern 1 — 12/13, the polish target; A6 tap juice; `vampire-survivors-stage-selection.jpg` green START as the only saturated element).** Keep the FAB persistent in the thumb zone (`renderSortieFab`, id `#start-defense` unchanged) but make it the **only cinder-ember-filled element** on the surface, with sub-100ms scale + pooled-particle tap feedback, and on-press the aperture "descends" into the abyss (opacity/transform tween, reduced-motion parity). Never gate it behind the briefing (constraint 6: play path bypasses management).

- **Theatricalize idle-return as the "payday" recap (A1 — highest impact, already-owned system; AFK-Arena welcome-back ref).** On load, before the docks settle, play a bounded recap over the live scene using `idleReturnSummary()`'s existing outcomes verbatim: SETTLED → zenith-gold count-up "봉쇄선이 버텼습니다 · +N 기록 · 누적 M" with a light particle rise; ENCROACHED → cinder-ember "저지선 압력 초과" with the existing *no-loss* reassurance surfaced as a beat, not fine print. It then folds into the sortie panel's 다음 보상 line so the payday points straight at the next sortie. **Skippable on tap, never blocks the FAB** (constraint 6 + Lane C anti-"forced login / shallow-login" backlash) — a reward for returning because time actually passed (`idleReturnReceipt`), not a daily leash. Replaces the silent toast; the persistent copy stays in the 요새 recap (`renderStrongholdTab`'s `.idle-return-recap`).

- **Discipline the palette so color = meaning, not soup (A5 + constraint 4).** Panels stay `--canon-void-obsidian`/rc-glass; the abyss beyond the aperture carries the warmth (`--canon-cinder-ember` = front heat/threat) and the cold rift-light (`--canon-cyan-rift`); **`--canon-zenith-gold` is reserved exclusively for reward/payday numbers** (idle count-up + 다음 보상 chip). Gold appears only where a reward is — that is the anti-currency-soup rule made visual.

This is the "map," not a wallpaper — it should look like the player is looking at the actual enemy front.
- **Right dock (전황 덱, open) = the command instruments,** `--canon-void-obsidian` rc-glass panels that read as bolted to the aperture rim (slight depth/parallax against the scene, per A6). Below: the **stage rail as a connected 봉쇄선 spine** — 3–4 art cards strung on a thin blockade line with node dots (one lit "선택됨/current," one dark "잠김," cleared ones marked held), each card showing its art + a small threat tag + a `--canon-zenith-gold` reward chip.
- **Briefing region = threat-read, reward-forward (not a `<dl>`):** the selected boss portrait, one threat sentence, and a prominent **"승리 시 → [다음 보상]"** gold chip as the headline; a small collapsed **"전황 상세 ▸"** disclosure hints the terrain stats live behind it (closed by default). A single compact read-only "출정 편성" row (front companions + one trait) sits beneath as the loadout glance.
- **Primary CTA = 작전 개시,** the ONE `--canon-cinder-ember`-filled element, anchored bottom-center in the thumb zone with a faint particle/charge halo — unmistakably the thing you press.
- **Top-left, as an overlay beat = the idle "payday" recap** mid-count-up: a `--canon-zenith-gold` "봉쇄선이 버텼습니다 · +N 기록" number rising over the scene with light particles, visibly dismissible — shown here to convey the re-entry moment, understood to fade before play.
- Overall read: a war-room looking into the abyss, gold only on rewards, ember only on the commit and the front's heat, cold rift-blue on the world — dark-fantasy 심연, not generic sci-fi.

## Risks / disagreements

- **vs Programmer (canvas reactivity + payday cost):** I expect pushback that swapping the boss mesh / re-tinting the scene on every stage-select and running a count-up recap competes with the single browser thread shared with combat and hurts first-paint (~53% mobile bounce >3s). I pre-concede: reuse existing `meshRootForStageBoss`/`stagePresentationFor`, count-up is a JS tween on a *number* (not a shader), the aperture "descend" is opacity/transform, all reduced-motion-gated. But I will hold the line that *some* canvas reactivity is non-negotiable — a fully static canvas throws away pattern 13 (the 1–2/13 "living background" that is our only structural advantage). Let's negotiate the exact reactive budget, not whether it exists.
- **vs UI (briefing demotion + spine crowding):** I push to collapse the five-row `<dl>` behind "전황 상세" and add a connector spine + on-card reward chips; UI may argue the current stats are already legible and that spine + chips crowd the tight mobile viewport and risk relocating learned structure (constraint 5). Resolution I'll offer: keep the `<dl>`'s DATA untouched, only change default visibility and promote the threat line + reward chip — this is theater layered on, not navigation moved.
- **vs PM (payday vs friction/manipulation):** the payday recap and the aperture-descend both add motion between the player and the START — exactly the friction players route around (constraint 6), and idle theater brushes the documented "manipulative daily-login / shallow-login" backlash. Non-negotiables from me: the recap is tap-skippable and never blocks the FAB; it fires only on real elapsed time, points at the next sortie (reward, not leash), and adds zero new economy (`idleReturnSummary` outcomes reused verbatim).
- **General risk (over-theater = the #1 complaint):** every addition here must be reward-forward and progressively disclosed, or it becomes the "cluttered / currency soup" the survey names as the top failure. The palette discipline (gold = reward only) and the "collapse terrain stats by default" rule are my guardrails against my own proposal tipping into clutter.
