## 0. What Abyss Depth does today (the thing that "changes nothing")

- **Scale only:** `effScale = run.stage.scale + depth * ABYSS_DEPTH_SCALE_STEP` where `ABYSS_DEPTH_SCALE_STEP = 15` → enemy HP and XP `scaled()` up +15%/tier — `defense-run-simulation.js:37-38,655-662`.
- **Wave-seed fold:** depth only reroutes the WAVE rng (`waveSeed`, `defense-run-simulation.js:3115`); identity/combat/surprise rng stay on the base seed, so depth "rotates which policies/compositions roll" but never *pins* a distinct mix — `defense-run-simulation.js:3113-3115`, `buildWaveSchedule` L425-507.
- **Text badge:** `depthBadge = " · ABYSS DEPTH n"` appended to the terrain-context HUD line — `app.js:2716-2717`; sortie label `심연 n` at `app.js:1466`; selector option text `적 +${d*15}%` at `app.js:1501`.
- **Net player-facing delta:** bigger HP bars, a longer time-to-kill, a badge string. No new enemy behavior, no new threat shape, no new stakes. This is why it reads as **stat inflation** (see §3).

The wave-seed fold is the ONLY behavioral hook already wired to depth — and it is a *weak* one: normal waves leave `policyId` unpinned (only `big`/`mid` waves pin, `defense-catalog.js buildDoctrineWavePlan:717-723`; normal waves fall through to the seeded pool in `defense-run-simulation.js buildWaveSchedule:475-476`) so depth just reshuffles the same per-class pool (`policyChoices` L429-434), it never changes the *distribution* of roles a player fights.

### Cross-cutting facts that constrain any lever
- **Determinism contract:** depth must not perturb the identity/combat rng or byte-identical depth-0 digests break (`defense-run-simulation.js:33-36,3112-3115`; demo verification `CHANGES-WALKTHROUGH.md:43`). Any new depth lever should fold into the **wave rng** or be pure authored data.
- **Reduced-motion:** shake/knockback/VFX motion are all reduced-motion-guarded (`battle-realtime-three.js:517,3517,3636`; `camera-vfx-direction.md` §6). Every felt beat MUST have a color/shape/audio equivalent, so a "tint + toast + cue" bundle is the accessible baseline.
- **Presentation is renderer-owned:** camera/VFX/shake/tint never write simulation state (`action-combat-spec.md` §1). A depth *tint* or *toast* is legal renderer work; a depth *policy pin* is simulation authored-data work.

## 3. Feel gap — why "+15% HP + badge" reads as stat inflation, and the cheapest fixes

### Why it reads as a stat tweak
1. **Nothing new *acts* on the player.** The four enemy archetypes pursue the same targets with the same policies; depth only reshuffles a per-class pool (L1) and never *pins* a different role distribution (only big/mid waves pin policy — `defense-catalog.js buildDoctrineWavePlan:717-723`; normal waves fall through to the seeded pool `defense-run-simulation.js buildWaveSchedule:475-476`). Same enemies, same intents.
2. **The only felt change is time-to-kill.** +15% HP (`effScale` L655) makes every body take longer to drop; XP scales with it (L662) so even the level-up cadence is held constant *by design*. The player experiences "the same fight, slower" — the textbook definition of a stat-stick (`dead-cells.json:10` "STAT-STICK" complaint; RoR2 "delete or be deleted" `risk-of-rain-2.json:10`).
3. **No entry moment, no stakes signal.** Depth is a badge string appended to a HUD line (`app.js:2716-2717`) and a sortie-label suffix (`app.js:1466`). There is no announce, no screen change, no visible reward delta — the game never *says* "this is different," so the brain files it as a number.
4. **The camera/audio escalation the engine already has isn't triggered by depth.** Big-wave/midboss camera tiers (`battle-realtime-three.js:739-751`) and warning cues (`defense-audio.js:199-225`) fire on wave *kinds*, and depth doesn't change wave kinds — so all the built-in "this is intense" framing sits unused per tier.

### The 3–5 cheapest current-code changes that make a depth tier read as NEW CONTENT
All are LIVE-lever edits (authored data + existing event paths), determinism-safe (wave-rng / authored data only), and reduced-motion-safe (each has a non-motion equivalent). Ordered by impact-per-cost.

1. **Force a distinct enemy-policy mix per depth (L1) — highest impact, cheapest.**
   Pin `policyId` per depth in the wave schedule (today only big/mid waves pin — `defense-catalog.js buildDoctrineWavePlan:717-723`; normal waves fall through to the seeded pool `defense-run-simulation.js buildWaveSchedule:475-476`). e.g. D2→`player-pursuit` dominant (enemies hunt the commander, not the gate), D3→`resource-denial` dominant (echoes denied, sustain starves via `ECHO_DENIED` L2406 / `run.progress.echoDenied` L2395), D4→`flank`+`low-hp-focus`. The enemy *math* changes, so a single build stops solving every tier (`gap-analysis.md` GAP-C; `2026-07-30-onslaught-pivot-gap-additions.md` §GAP-C L75). *Cost: authored per-depth policy table + one lookup in `buildWaveSchedule`.*

2. **Add an elite affix / extra threat per depth (L4) — the "mini-boss got scarier" beat.**
   The elite spawn is a single hardcoded block (`defense-run-simulation.js:2881-2904`, `low-hp-focus`, one guardian escort). Per depth: swap the elite's policy to something hostile, add a second escort, or scale its ×4 HP multiplier (`spawnEnemy:679`) independently of the flat +15%. Elite already owns bespoke camera framing and `elite-extracted` audio (`defense-audio.js:203`), so a behavior change reads as a redesigned encounter, not a fatter bar. *Cost: parameterize the elite spawn block by depth.*

3. **Screen tint + announce toast on depth entry (L14 + L8) — the legibility fix.**
   On run start at depth>0, fire a `showToast` ("심연 n 진입 · <지배 정책> 활성" — naming the #1 policy change) plus a brief renderer-side color wash (the per-stage palette-tint machinery already exists — `battle-realtime-three.js:597,2121-2201` — a depth overlay is the same primitive) and reuse an unused audio cue (`boss-phase`/`warning-pulse`, `defense-audio.js:138-141,199`). This is the single highest-legibility signal that "this is a different mode." Reduced-motion equivalent = the toast text + tint (static) + cue. *Cost: one toast call + one tint constant + one cue emit; no sim change (pure presentation).*

4. **Escalate wave shape, not just HP (L2 + L7) — makes the fight denser, and the camera reacts for free.**
   Per depth, shift `kindCycle`/`classes` toward more `big`/`mid` waves and/or raise the ramp/pressure (`defense-catalog.js:646-650`, `buildDoctrineWavePlan:688-716`, `WAVE_PRESSURE_BP:671`). Because `WAVE_VARIANT_STARTED kind=big` and `MIDBOSS_SPAWNED` already drive the BIGWAVE/MIDBOSS camera tiers (`battle-realtime-three.js:743-751`) and warning cues (`defense-audio.js:199,225`), denser depth *automatically* gets more dramatic framing and sound — no extra juice code. *Cost: per-depth doctrine overrides (authored data).*

5. **Gate a visible reward multiplier on clearing each depth (L5) — turns difficulty into stakes.**
   The `TERMINAL` event already carries `rewardChoices` (`defense-run-simulation.js:3030-3036`) and the run-end toast already exists (`app.js:3510-3512`). Attach a depth-scaled bonus reward or multiplier and *surface it in the sortie selector and result card* so the player sees the payoff climb — this is the Hades-Heat / RoR2-Eclipse / Dead-Cells-BSC consensus pattern for making a re-run of fixed content feel worth it (`hades.json:11`, `risk-of-rain-2.json:11`, `dead-cells.json:11`). *Cost: reward-table depth mapping + display strings.*

**Bundle recommendation:** #1 + #3 + #5 is the minimum viable "new content" depth — it changes *what enemies do* (feel), *tells the player it changed* (legibility), and *makes it worth doing* (stakes) — all on current code, determinism-safe, for roughly the cost of the +15% patch it replaces. #2 and #4 deepen it. The pivot-era boss-phase/dodge-pattern/hitstop levers (§2) are the eventual ceiling, but are not required to escape the stat-inflation read.
